# Agent 首轮效率优化验证

日期：2026-10-17。保留聊天模型、high思考、人设、历史预算和业务校验，优化发送收尾及上下文重复。

## 真实 API 合成回放

使用相同的新上下文组织方式，仅切换 `AGENT_BATCH_COMPLETION_ENABLED`，每个任务每种模式各运行一次。数据库、群成员和发送回调都是合成的，不向真实 QQ 发送，不在生产数据库创建提醒。

| 任务 | 模型轮次：关闭→开启 | 累计输入token：关闭→开启 | 累计输出token：关闭→开启 |
| --- | --- | --- | --- |
| 从多人群聊中回答约定时间 | 3 → 1 | 19,228 → 6,411 | 171 → 78 |
| 私聊创建一次性喝水提醒并确认 | 3 → 2 | 16,390 → 10,878 | 215 → 193 |

两种模式均完成相同任务；提醒确实写入临时数据库后才发送确认。每次请求都取得API的usage计数。

输入token累计下降约66.7%和33.6%。这是两个合成样本，不能当成线上平均节省率；缓存命中和推理输出也会变化，因此不直接换算账单降幅或声称固定速度提升。输出token已包含提供商报告的推理部分，不重复相加。

上述结果为当时的一次性测量记录，原测量脚本已清理。后续回放使用项目外的临时脚本，真实API调用仍会产生费用。

## 离线上下文对比

与优化前提交 `1074522` 的群聊上下文构造器比较。在同一组24条带引用关系的合成消息上，保留消息数相同，历史文本从11,248字符降到6,508字符，减少42.1%。主要消除了重复引用正文、空字段及JSON空白；这项测量是字符数，不是token数。

## 回归与后续测量

回归覆盖合并发送/等待/结束、发送前参数校验、失败后继续决策、传输未确认不重发、收尾后禁止追加动作、关闭优化恢复分步流程，以及原有群聊结构与记忆测试。

线上 `Agent finished` 日志新增模型轮次、累计输入/输出/推理token、输入缓存命中token与提供完整usage的请求数。先积累真实分布，再评估工具目录裁剪、人设规则去重或思考强度分级；本轮没有降低模型/思考等级，也没有额外增加“路由LLM”。
