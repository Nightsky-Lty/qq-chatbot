# 提示词与上下文

`PromptBuilder`是聊天提示词组装入口：system说明身份、资料信任、工具执行和场景，动态资料放在单独的user消息中。当前上下文版本为4。聊天原文与媒体识别结果均是资料，不是system指令。

## 连续原文

群聊每次从SQLite读取本批之前最近`CONTEXT_MESSAGE_LIMIT=30`条有效原文，不按话题分类、关键词挑选或推断语义关系。当前批次单独提供，后到消息不提前注入；窗口外同群真实引用最多补充4层祖先。字符不足时保留连续尾部，不跳过中间消息继续抽取更早内容。

程序内部保存结构化快照，最终由`chat_transcript.py`转换为简单JSON数组：每条以`user`、`message`为主体，补充`id`、`time`、`message_id`及实际存在的`at`/`reply_to`。机器人真实历史带`role=assistant`，`in_reply_to`表示程序记录的实际回应对象，不表示QQ显示了引用框。原话与昵称使用JSON转义，换行不会冒充另一条程序记录。

聊天数组的主体如下（运行环境与工具约束另行提供）：

```json
{
  "聊天记录": [
    {"id": 1, "user": "小明(QQ11)", "message": "今天终于下班了"},
    {"id": 2, "user": "小鲸鱼（你）(QQ90)", "role": "assistant", "message": "辛苦啦"},
    {"id": 3, "user": "小明(QQ11)", "message": "明天又要早起"}
  ],
  "当前任务": {"新消息ID": [3], "建议焦点ID": 3}
}
```

动态消息包括运行环境、背景资料和当前任务。焦点是推荐起点，回复模型结合整批新消息理解回应对象，可以自然跟随新话题；每轮围绕一处新交流，不逐条补答历史。同一群聊天任务串行，不同群可以并行。

私聊仅使用当前用户独立窗口。历史不扩大引用、@或附件操作权限。原文截断会明确标注，更早查询可以重新读取该条。

## 多模态文本

`models.py`提取有界安全消息段，并用`parts_json`保存顺序；只有文本、@、图片位置、未解析媒体标记与卡片元数据，不保存附件下载地址或本地路径。旧记录按正文与已有图片缓存显示。

图片由现有概要模型后台识别，按内容哈希去重复用。`media_text.py`在对应消息的原始图片位置插入`<image>`，区分画面、图中文字和识别不确定性，标明自动识别、非用户原话。单图画面/OCR各最多240字符，单条消息派生说明最多2400字符，超额显示缩略提示。完整结果仍保存在缓存，可按需查看原图。已经嵌入的说明不在附件目录重复注入。

识别未完成、失败或没有可用编号时如实标记。`get_message_image`仍用于精确读字和画面核对，聊天图与表情原图每轮合计最多3张。描述不证明用户身份、经历或意图，也不会自动成为长期事实。

语音与视频目前显示`<audio 内容未解析 />`和`<video 内容未解析 />`，没有ASR或抽帧识别。JSON分享卡片仅提取平台、标题和简介，以`<embed>`标注为元数据、正文未读取；不自动打开小程序、请求卡片URL或播放视频。

## 人设与工具

`CORE_PERSONA`常驻，可选外貌、互动和生活细节每次普通聊天最多加载两个，整个Agent执行内固定。规则先核对是否谈机器人自身；必要时复用BGE和公开说明向量缓存，相似度至少0.48、候选间隔至少0.08、最多等待2秒。哈希回退或超时只保留核心。`PERSONA_DETAILS_ENABLED=false`关闭可选片段。

基础发送/收尾与`search_tools`常驻；其他工具由本地embedding检索top-k及必要依赖。工具schema负责参数，能力补充说明仅在工具加载后注入；注册表及执行器校验权限，检索不扩大授权。

更早群聊使用[read_chat_history](chat-history.md)，游标绑定当前群、本轮任务与消息边界，不调用额外分类模型。工具结果保留在真实assistant/tool链，不伪造新群友发言。

## 长期记忆

`MEMORY_AUTO_RECALL_ENABLED=false`默认不自动检索旧资料；后台提取及事件/抽象/图片记忆和六个记忆工具继续工作，模型可主动调用`memory_search`。开启自动召回时，原句是主查询，含糊短追问最多补充3段、每段240字符的当前原文线索；日期、层和回忆触发只读原请求。补充路径由`MEMORY_CONTEXT_QUERY_ENABLED`控制，不调用查询改写LLM。

自动注入或调用方提供的长期记忆由`memory_view.py`生成紧凑行，保留编号、版本、依据、来源、条件、不确定性、时间及资源引用。数据库和记忆工具保留完整结构，修改仍校验编号和版本。

## 执行与验证

当前任务内`reasoning_content`、tool_calls、tool_call_id与工具回执继续完整传回，不摘要或裁剪。本轮结束释放任务证据与查询缓存。字符限制仅约束聊天/媒体视图，不是统一token预算。

现有测试用`python -m unittest discover -s tests -v`运行；部分断言依赖旧窗口、提示词形状或工具接口，全量尚未通过。专项验证按项目约定放在仓库外临时执行，不新增回归测试。结构验证不代表实际语义质量已经提高，指代、反讽与误接话仍需使用观察。
