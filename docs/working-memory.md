# 对话工作记忆

`WorkingMemory`现在表示按群/私聊隔离、跨回复保留的短期对话语境，不再表示单次Agent的消息列表。原始记录仍在SQLite；短期缓存和摘要不是新的事实权威或授权依据。

## 数据流

1. 群友互聊（不要求唤醒）、私聊用户消息、确认发送的机器人回复入库后，立即通知`WorkingMemoryManager.receive`，不调用LLM。原本提前分流、不进聊天库的管理命令仍不进入。
2. 首次访问/重启时，从当前会话、保留期内最多128条原话冷恢复一次有界窗口。后续按消息增量更新，不再每轮重拼80条时间线。摘要只在内存，重启后不恢复旧摘要。
3. 回复前按本批消息边界生成快照，注入`背景资料.短期记忆`，包括`语境摘要`、`近期往返`和来源说明。当前请求单独放在`当前任务`，相关长期记忆仍独立检索。
4. 默认优先选择最近12条原文候选、焦点相关片段、相邻往返及最多4层明确引用；总预算默认8000字符，同时服从`CONTEXT_MAX_CHARS`。不是固定12条，也不是上传整个128条缓存。
5. 较早原文积累到24条、还能留下12条近期原文时，后台复用独立记忆模型更新最多8条、每条最多200字的语境笔记。类型为topic/pending/correction，维护并行话题、人物交流关系、指代、纠正和未解决请求；不开放工具、不使用聊天人设、不产生长期记忆增删动作。图片概要与来源单独标记，不冒充用户原话。
6. 压缩片段、空闲淘汰和显式整合可将真实来源交给现有持久整合队列，筛选成事件/抽象长期记忆。每批Agent结束时仍交接本批新证据；未唤醒Agent的普通消息仍有原来的增量整理兜底。在整理锁内核对来源归属和游标，已处理/已分配来源不重复当成新证据。

## 生命周期与降级

- 普通回复、`finish/wait_for_messages`、Agent报错或取消不会清空会话语境。
- 每条来源默认保留30分钟，会话空闲30分钟后逐出内存。最多64会话、每会话128条原文，LRU/容量淘汰可早于保留期。
- 高流量、无Key或摘要失败时仍保留有界原文；SQLite和原话入库时已有的持久增量整理队列不受缓存淘汰影响。关闭服务时不等待外部模型。
- 摘要请求最多等待30秒，失败/无Key默认60秒退避。关闭摘要仍可使用短期原文，不为每次回复增加前置摘要调用。
- 摘要会额外消耗记忆模型请求，总token费用是否下降需实测，不能仅比较聊天请求长度。
- 目前只支持单实例/单进程，不跨进程共享短期缓存。重启会丢失摘要组织，但不会删除原话或长期整合任务。

## 证据与遗忘

正群号、负私聊QQ为不同空间。快照、摘要回查、图片资料受本批边界约束；后到消息及其摘要不能提前进入本批。摘要必须引用模型实际获得的1至8个来源ID，不允许任意编号。

原话优先于摘要；摘要中的旧请求不能成为新授权。添加/更新/删除/遗忘仍依据本人本轮真实新证据，群共享概念仍由已验证管理员管理。机器人说“我会处理”不证明工具已执行，操作状态仍由实际工具与业务数据库维护。

每次快照、压缩提交、来源展开重新核对数据库、保留期和遗忘阻断。摘要记录整个模型输入及旧摘要的依赖，不仅相信模型自报的支持来源；任一输入来源被删除/遗忘/到期，整条摘要失效。输入依赖越过当前批次也不注入。递归依赖过长则舍弃旧摘要线索，重新依据新原话整理，避免无限增长。在途摘要不能恢复旧内容，既已发给提供商的上下文不可撤回，当前工具链不为此随意截断。

整合传真实来源，不把短期摘要作为新事实，不保存推理、网页结果或工具草稿。排队不等于长期写入成功。关闭`MEMORY_AUTO_CAPTURE_ENABLED`后不自动归档，短期缓存仍可独立工作。

## 工具与本轮状态

`memory_search(layer="working")`返回真实短期快照，`include_sources=true`最多展开3条摘要依据原文；working层不支持subject/after/before过滤。`memory_consolidate()`提交当前边界内尚未归档的原话，不清空正在使用的短期语境。

本轮`messages/CoT/tool_calls/回执`仍在`ReactAgent`局部变量，发送确认、去重、计数、等待/结束仍在`ToolRegistry/MessageSession`。整批工具处理完才再次调用模型，没有新增执行状态LLM。

原工作区里的来源、任务编号、查询缓存迁移到`TaskEvidence`，结束释放；不持有模型消息链。`open_workspace/close_workspace`保留原方法名，实际返回任务证据对象。

## 配置

默认值均在`config.env`；不新增密钥，摘要复用`MEMORY_LLM_*`。

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| WORKING_MEMORY_ENABLED | true | 启用短期快照；false回退旧历史组装 |
| WORKING_MEMORY_TTL_SECONDS | 1800 | 来源保留/会话空闲淘汰时间 |
| WORKING_MEMORY_MAX_SCOPES | 64 | 内存会话上限 |
| WORKING_MEMORY_MAX_MESSAGES | 128 | 单会话原文上限 |
| WORKING_MEMORY_RECENT_MESSAGES | 12 | 近期原文候选数 |
| WORKING_MEMORY_CONTEXT_MAX_CHARS | 8000 | 注入字符预算 |
| WORKING_MEMORY_COMPACT_BATCH | 24 | 后台压缩的较早原文数 |
| WORKING_MEMORY_SUMMARY_ENABLED | true | 后台语境整理开关 |
| WORKING_MEMORY_RETRY_SECONDS | 60 | 失败/无Key退避 |

近期原文数加压缩批次不得超过缓存容量。`CONTEXT_MESSAGE_LIMIT/CONTEXT_BOT_REPLY_LIMIT`只用于旧历史回退。

## 验证

执行`python -m unittest discover -s tests -q`。`tests/test_working_memory.py`覆盖持续接收、跨回复、多人/跨空间、未来批次、预算、后台压缩/失败退避、图片来源、归档去重、删除/遗忘、在途失效、TTL/LRU、冷恢复、工具搜索及来源展开；原有图片收藏、真实发送和长期记忆测试继续保留。

测试使用合成对话和模拟模型，真实模型的聊天理解、摘要准确率及成本收益仍需线上评估。
