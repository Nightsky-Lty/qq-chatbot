# 对话工作记忆

`WorkingMemoryManager`维护按群/私聊隔离的真实原文，不生成LLM短期摘要。原文持久保存在SQLite，内存登记用于近期缓存与空闲归档；推理、工具回执和查询缓存属于单次Agent，不进入聊天历史。

## 原文窗口

每次读取当前批次之前最近30条有效历史，排除已遗忘/删除来源，按原始顺序保留所有作者的连续往返。当前批次单独注入，后到消息不会挤掉历史或提前进入本轮。窗口不按关键词或话题筛选。

窗口外真实引用可单独补充最多4层祖先，仍检查同群、边界和来源有效性。预算不足仅保留连续尾部，不跳过中间消息再挑选更早内容。单条过长时明确标记截断，历史工具可重新读取该条；远端引用不会改变默认翻页起点。

媒体识别说明按消息段顺序嵌入对应消息，标注自动识别、OCR与不确定性。完整识别缓存、原图查看和附件授权独立维护。格式详见[提示词与上下文](prompt-context.md)。

## 生命周期与整合

- 普通群友互聊、私聊和确认发送的机器人回复入库后通知缓存。
- `wait_for_messages`维持活跃跟进，`finish`结束跟进，都不删除历史。群聊任务按群串行；活跃期群内连续3分钟无人发言自动结束跟进，新群友消息续期，机器人回复不续期，整段活跃最长30分钟。
- 默认30分钟TTL只淘汰空闲内存。重启、容量不足不影响SQLite恢复，低频群的数小时前原文仍可进入近期窗口。
- 群使用正群号，私聊使用负QQ号作为命名空间，不能互相读取。
- 关闭内存工作记忆登记后，群聊和私聊仍从SQLite读取当前会话连续原文，并保留向前翻页起点。

普通未唤醒消息仍可由后台按默认30秒/40条增量提取；任务结束提交真实新消息与成功回复。空闲归档及`memory_consolidate`继续使用真实来源，保留权限、版本、去重、遗忘阻断和索引同步。默认关闭自动长期召回，模型需要时调用`memory_search`，后台整理不受影响。群聊和私聊原文向前读取均使用[read_chat_history](chat-history.md)，分别限定当前群或当前用户。

## 配置

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| CONTEXT_MESSAGE_LIMIT | 30 | 群/私聊近期历史条数，不含当前批次 |
| CONTEXT_MAX_CHARS | 24000 | 聊天原文视图字符上限 |
| WORKING_MEMORY_CONTEXT_MAX_CHARS | 24000 | 与上述上限取较小值 |
| WORKING_MEMORY_ENABLED | true | 内存登记和空闲归档 |
| WORKING_MEMORY_TTL_SECONDS | 1800 | 空闲淘汰时间 |
| WORKING_MEMORY_MAX_SCOPES | 64 | 内存会话数上限 |
| WORKING_MEMORY_MAX_MESSAGES | 128 | 每会话内存登记上限，不限制SQLite恢复 |
| MEMORY_AUTO_RECALL_ENABLED | false | 自动注入长期记忆，自主检索和后台整理不受影响 |

字符上限不含system、工具schema与真实工具链，不等于token预算。现有测试部分旧窗口和接口断言与当前行为不一致，专项检查在仓库外临时执行。
