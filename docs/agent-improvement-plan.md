# Agent 后续改造方案

状态：2026-10-17 已按最终确认方案实施；以下保留设计依据，实际行为以 README 和代码为准。

实施结果：独立表情标记/记忆客户端与可配置模型；群/私聊后台增量记忆提取、来源校验、语义键版本与有效期、回忆及显式记住/遗忘工具；群聊历史改为带真实引用和寻址依据的去重时间线。暂不增加前置群聊理解LLM调用，继续由聊天LLM理解。随机接话和唤醒机制不变。

## 已确认：独立 LLM 职责

将聊天、表情包入库标记、长期记忆处理拆成独立的 LLM 调用职责。可复用同一家服务和同一模型，但各自有独立的提示词、输入、输出及权限；后续支持按职责配置模型和连接参数，未指定时复用已有配置。

- 聊天 LLM：理解当前对话，决定聊天回复和即时工具动作，使用检索到的记忆。
- 表情包标记 LLM：分析图片、文字、情绪、适用场景和审核结果，仅输出受校验的结构化数据，不发送聊天消息。现有 `annotate_sticker` 已是独立请求，后续主要补足独立模型配置与资源管理，不重复建设已有标记流程。
- 记忆提取 LLM：对真实对话做后台提取，提出新增、合并、更新或失效记忆的建议；程序校验并写库。普通记忆不再依赖聊天 LLM 主动调用保存工具；显式“记住/忘掉”请求保留同步处理入口。

独立调用不等于必须部署多个模型，也不等于必须创建多个可自主调用工具的 Agent。工具执行和数据库变更仍由程序控制。

## 长期记忆的实施方向

1. 接通私聊长期记忆，按群或私聊会话隔离，默认不互通。
2. 在实际回复后异步提取，可合并多轮对话；群聊未触发聊天 Agent 的普通消息也应有受控的提取入口。
3. 区分人物事实与双方共同经历/约定。保存原文摘要、所属对象、来源消息、时间、有效状态和向量。
4. 来源包括用户原话、机器人实际发送成功的回复及工具回执；机器人说“已完成”不能代替工具执行证据。
5. 保存候选前校验身份、会话、来源和敏感信息。允许输出空候选，不要求每轮必须保存。
6. 支持语义去重、事实变更、旧版本失效、限时事件过期、用户纠错和遗忘。模型自报置信度不能替代证据。
7. 记忆文本新增或修改时生成 BGE 向量；检索先做会话/身份/有效状态过滤，再结合语义和关键词排序。
8. 保留自动召回，增加按需查询旧事的入口。以真实回归样例评估写入、召回、身份归属和回复使用效果。

## 群聊结构理解：问题依据与设计备选

用户反馈：机器人有时把群友之间的对话当成对自己的请求；即使提供了历史，也会误解话题含义。

代码检查依据：

- `GroupMessage.eligible` 通过 @ 和显式引用排除部分第三方对话，但无 @、无引用只表示指向不明，当前会成为候选，并非证明是在对机器人说话。
- `GroupBatch.focus` 根据明确触发、同人后续或最后一条候选选择焦点；同一群只保留一个简短 topic，无法表达并行话题。
- 当前输入包括时间顺序历史、单独的机器人回复历史及当前发言人较早发言。普通历史没有显式时间字段、结构化 @ 目标及展开的引用链；零散个人发言可能缺少原对话另一方。
- 同一个批次的 `direct` 标志会作用于整轮，但焦点可能已换成后续消息；需要保留每条消息的寻址依据和与触发消息的关系。
- 随机唤醒提示词要求必须发言，不能在语义判断为不适合介入时保持静默。这会增加对第三方对话插话的机会。

建议后续设计：

1. 明确提供机器人身份；每条消息保留作者、时间、@ 目标、显式引用及已知的原消息关系，区分真实元数据与推断。
2. 将“程序允许考虑回应”与“消息确实对机器人说”分开。寻址状态至少区分对机器人、对他人、群内广播、无法确定；推断记录依据和不确定性。
3. 从平铺历史改为相关对话片段：优先显式引用链、当前互动及必要前文，保留完整往返；区分并行话题，而不是只增加历史条数。
4. 随机触发只给一次参与判断机会；明显是第三方对话或含义不明时允许等待，不强制插话。明确 @ 或命令仍正常回应。
5. 可评估增加独立的群聊理解调用，先输出参与者、话题、发言对象和可参与性，再交给聊天 LLM；此项尚未确认，先评估额外延迟及误判传播成本。
6. 用去标识化回放测试覆盖多人并行、第三方引用、机器人回复的续接、无 @ 省略句和话题切换；同时测“该回应却沉默”和“不该回应却插话”，不只测回复流畅度。

最终决策：先完善输入结构，暂不实施第4项随机唤醒改动或第5项额外理解调用。后续根据真实聊天回放评估，而不是预先增加模型层级。
